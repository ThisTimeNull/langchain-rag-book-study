# Q0020 · 생성 단계는 어떻게 평가하나? (정답셋, LLM 채점, 반복 실행)

- **태그**: vectorrag
- **날짜**: 2026-09-19
- **코드**: [`code/Q0020_generation_eval.py`](../code/Q0020_generation_eval.py)

## ❓ 질문
Q0019에서 같은 코드를 세 번 돌려 세 번 다른 답을 얻었고, 눈으로 채점하다 틀린 서술을 남겼다.
답변을 기계가 채점하게 하려면 뭘 만들어야 하나?

## 💡 한 줄 답
> 정답셋, LLM 채점기, 반복 실행 세 가지다. 그런데 **채점기부터 틀렸다.**
> 처음 만든 채점기는 같은 답에 2점, 0점, 1점을 번갈아 줬고, 부당한 거부 15건을 전부 "적절"이라고 했다.
> 채점기를 고친 뒤 점수가 13/21에서 **8/21로 내려갔다.** 그게 진짜 점수다.

## 📖 설명

### 무엇을 재나

검색 평가(Q0008)는 "맞는 조각을 가져왔나"였다. 생성 평가는 "가져온 조각으로 맞는 답을 썼나"다.
세 가지를 따로 본다.

| 기준 | 무엇과 비교 | 묻는 것 |
|---|---|---|
| 정확성 | **정답**과 | 답이 정답과 같은 내용인가 |
| 충실성 | **근거**와 | 근거에 없는 말을 지어냈나 |
| 거부 판단 | 정답 유무와 | 모른다고 해야 할 때 모른다고 했나, 그 반대는 아닌가 |

정확성과 충실성은 다르다. 근거에 답이 없어서 "찾을 수 없습니다"라고 하면, 충실성은 만점이고
정확성은 0점이다. 아무것도 안 지어냈지만 답도 못 했으니까.

### 만든 것

**정답셋**: Q0019의 대본 7개에 정답을 한 줄씩 붙였다. 예를 들어 "그 논문 저자는 몇 명?"의
정답은 "8명"이다. 사람이 PDF를 읽고 적었다.

**채점기**: `with_structured_output(Grade)`로 LLM에게 정확성과 충실성을 0~2점으로 받는다.
채점 이유도 한 문장 받는다. 채점기가 틀렸을 때 사람이 알아볼 수 있어야 하기 때문이다.

**반복 실행**: 대본 7개를 3회 돌린다. 매 회 대화 기록을 새로 시작한다. "3회 중 몇 회"로 낸다.

### ⭐ 발견 1: 채점기가 정확성과 충실성을 섞었다

첫 채점기의 결과다.

```
4. 어텐션 수식은?      답: "찾을 수 없습니다"   → 정확 2, 2, 2
5. 저자는 몇 명?       답: "찾을 수 없습니다"   → 정확 0, 0, 0
7. 가장 먼저 나온 건?  답: "찾을 수 없습니다"   → 정확 2, 0, 1
```

같은 답에 점수가 제각각이다. 4번 채점 이유를 보면 이렇다.

> "근거에 해당 수식이 없으므로 '문서에서 찾을 수 없습니다'라고 답한 것은 정확하고 충실합니다."

**근거를 보고 정확성을 매겼다.** 정답은 수식인데 근거에 없으니 "찾을 수 없다"가 맞다고 한 것이다.
프롬프트에 "정확성은 정답과 비교"라고 썼는데도 그랬다. 7번은 실행마다 다르게 판단했다.
채점기도 LLM이라 흔들린다.

고친 프롬프트에는 규칙을 못 박았다.

```
정확성: [답변]이 [정답]과 같은 내용인가. [근거]는 보지 마세요.
  '찾을 수 없습니다'라고 답했는데 [정답]이 있으면 정확성은 0입니다. 근거에 있든 없든 상관없습니다.
```

고친 뒤 4, 5, 7번이 모두 0, 0, 0으로 일관됐다.

### ⭐ 발견 2: 거부 판단은 LLM이 할 수 없다

첫 채점기는 거부 판단도 LLM에게 시켰다. 21번 전부 "적절"이라고 했다.

이유가 있다. 채점기는 **검색된 근거만 본다.** 근거에 답이 없으면 "찾을 수 없습니다"가 적절해
보인다. 그런데 정답은 문서 어딘가에 있다. 검색이 놓쳤을 뿐이다. 채점기는 "검색이 놓친 것"과
"문서에 없는 것"을 구분할 방법이 없다.

이건 LLM에게 물을 일이 아니다. 정답이 있는 질문에서 "찾을 수 없습니다"라고 하면 그건 무조건
부당한 거부다. 문자열 검사 한 줄이면 된다.

```python
def refusal_flag(answer, gold_answerable=True):
    refused = "찾을 수 없습니다" in answer
    if refused and gold_answerable:   return "R"   # 답이 있는데 모른다고 함
    if not refused and not gold_answerable: return "H"   # 없는데 답을 함
    return "o"
```

고친 뒤 부당한 거부가 **0건에서 15건**으로 잡혔다.

### 결과 (고친 채점기, 3회)

| # | 질문 | 정확성 | 충실성 | 거부 |
|---|---|:---:|:---:|:---:|
| 1 | GraphRAG 핵심 주장 | 6/6 | 6/6 | ooo |
| 2 | 그걸 어떻게 증명 | 4/6 | 5/6 | RRR |
| 3 | 비교 대상 | 6/6 | 6/6 | ooo |
| 4 | 어텐션 수식 | **0/6** | 6/6 | RRR |
| 5 | 저자 몇 명 | **0/6** | 6/6 | RRR |
| 6 | RAG 논문 연도, 저자 | **0/6** | 2/6 | RRR |
| 7 | 세 논문 중 먼저 | **0/6** | 6/6 | RRR |

정확성 만점 8/21. 지어낸 답 0건. 부당한 거부 15건.

이 표가 말하는 것은 분명하다. **이 시스템은 지어내지 않는다. 대신 모른다고 너무 자주 한다.**
4~7번은 정답이 문서에 있는데 검색이 못 가져와서 답을 못 했다. 생성 문제가 아니라 검색 문제다.
생성 평가를 해보니 검색을 고쳐야 한다는 결론이 나왔다.

2번은 거부 표시가 RRR인데 정확성은 4/6이다. 답을 하면서 "세부 절차는 찾을 수 없습니다"라고
덧붙인 걸 문자열 검사가 거부로 잡은 것이다. 코드 판단의 한계다. 답 전체가 거부인지
일부만 거부인지는 구분 못 한다.

### 첫 채점기와 비교

| | 첫 채점기 | 고친 채점기 |
|---|:---:|:---:|
| 정확성 만점 | 13/21 | 8/21 |
| 부당한 거부 | 0 | 15 |

**같은 답변을 채점했는데 점수가 이렇게 다르다.** 첫 채점기를 믿었으면 "62% 정확"이라고 적었을
것이다. 실제는 38%다. 채점기를 검증하지 않으면 평가가 아니라 착시다.

### 채점기를 믿을 수 있게 하려면

이번에 한 것과 못 한 것이다.

| 방법 | 했나 |
|---|:---:|
| 채점 이유를 받아 사람이 훑는다 | ✅ 이걸로 첫 채점기의 문제를 찾았다 |
| 기계가 할 수 있는 판단은 코드로 (거부 여부) | ✅ |
| 기준마다 무엇과 비교하는지 프롬프트에 못 박는다 | ✅ |
| 사람이 채점한 표본과 채점기 결과를 대조한다 | ❌ 다음에 |
| 채점기도 여러 번 돌려 일치율을 본다 | ❌ 다음에 |

## 🔗 코드와 연결

```bash
.venv/bin/python code/Q0020_generation_eval.py            # 3회
.venv/bin/python code/Q0020_generation_eval.py --runs 5
```

| 이름 | 역할 |
|---|---|
| `GOLD` | 질문 7개와 정답 |
| `Grade`, `JUDGE` | 채점 스키마와 프롬프트. "근거는 보지 마세요" 규칙이 핵심 |
| `refusal_flag()` | 거부 판단을 코드로 |
| `run_once()` | 대본 한 바퀴. 네트워크가 끊기면 질문 단위로 재시도 |
