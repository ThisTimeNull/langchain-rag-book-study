# Q0019 · 진짜 PDF로 대화형 RAG를 만들면 어디서 깨지나? (논문 3편, 메모리, 출처)

- **태그**: vectorrag
- **날짜**: 2026-09-14
- **코드**: [`code/Q0019_pdf_chat.py`](../code/Q0019_pdf_chat.py)

## ❓ 질문
지금까지 문서는 전부 직접 만든 짧은 마크다운이었다. 진짜 PDF에 붙이고, 처음으로 대화를 하면
어디서 깨지나?

## 💡 한 줄 답
> 7개 질문을 두 번 돌렸더니 **한 번은 3승 4패, 한 번은 5승 2패**였다. 같은 코드, 같은 문서다.
> 안정적으로 실패한 건 2개(저자 수 세기, 세 논문 연도 비교)이고, 나머지는 실행마다 갈린다.
> 실패 원인은 **검색 실패, 대명사 되쓰기 오류, PDF 추출 한계, 벡터로 못 푸는 질문** 넷이다.

## 📖 설명

### 무엇을 만들었나

공개 논문 PDF 세 편을 골랐다. 지금까지 공부한 것의 원조들이다.

| 파일 | 논문 | 쪽 | 왜 골랐나 |
|---|---|---|---|
| attention.pdf | Attention Is All You Need (2017) | 15 | Q0018 트랜스포머의 원조 |
| rag.pdf | Retrieval-Augmented Generation (2020) | 19 | RAG라는 이름의 원조 |
| graphrag.pdf | From Local to Global (2024) | 26 | Q0015 전역 요약의 원조 |

60쪽을 800자 조각 316개로 자르고, 대화 기록을 들고 있는 `Chat` 클래스를 만들었다.
핵심은 [`Chat.ask()`](../code/Q0019_pdf_chat.py)의 세 단계다.

```python
# 1) 앞 대화가 있으면 질문을 완전한 문장으로 다시 쓴다
full_q = self.rewrite.invoke({"history": hist, "question": question})
# 2) 다시 쓴 질문으로 검색한다 (원래 질문이 아니라)
hits = self.retriever.invoke(full_q)
# 3) 답한다
```

"그걸 어떻게 증명했어?"를 그대로 검색하면 "그걸"이 뭔지 몰라 아무거나 나온다.
먼저 "GraphRAG 논문의 주장을 어떻게 증명했어?"로 바꾸고 그걸로 검색한다.

### 결과 (두 번 실행)

| # | 질문 | 1차 | 2차 | 원인 |
|---|---|:---:|:---:|---|
| 1 | GraphRAG 논문의 핵심 주장은? | ✅ | ✅ | |
| 2 | **그걸** 실험으로 어떻게 증명했어? | ✅ | ✅ | 되쓰기가 "그걸"을 정확히 풀었다 |
| 3 | **그 실험에서** 비교 대상은? | ✅ | ✅ | |
| 4 | 트랜스포머 논문의 어텐션 수식은? | ❌ | ✅ | 1차는 5, 6쪽만 가져옴. 2차는 4쪽을 가져와 수식까지 복원 |
| 5 | **그 논문** 저자는 몇 명? | ❌ | ❌ | 되쓰기는 맞았는데 검색이 graphrag.pdf로 감 |
| 6 | RAG 논문은 몇 년도에 누가 썼어? | ❌ | 반 | 1차는 되쓰기가 "RAG"를 "GraphRAG"로 바꿈. 2차는 저자 12명 맞힘, 연도는 못 찾음 |
| 7 | 세 논문 중 가장 먼저 나온 건? | ❌ | ❌ | 2차는 되쓰기가 "세 논문"을 "두 논문"으로 줄임 |

1차는 코드를 만들 때 돌린 것, 2차는 사용자가 터미널에서 돌린 것이다.
**같은 코드가 4번과 6번에서 다른 결과를 냈다.** 처음 문서를 쓸 때 1차만 보고 "4패"라고
적었는데, 그건 틀린 서술이었다. Q0014에서 "한 번 돌려서 맞았다고 된다고 말하면 안 된다"고
해놓고 반대 방향으로 같은 실수를 했다. 한 번 틀렸다고 안 된다고 말해도 안 된다.

### ⭐ 발견 1: 대화 이어받기는 된다

2번과 3번이 증거다. "그걸", "그 실험에서"를 정확히 풀어서 검색했다.

```
질문: 그걸 실험으로 어떻게 증명했어?
다시 쓴 질문: GraphRAG 논문에서 제안한 그래프 기반 RAG 방식이 대규모 텍스트 코퍼스에 대한
            전역적 설명과 인사이트를 실제로 제공한다는 점을 실험으로 어떻게 증명했어?
```

Q0016의 상호참조 해결과 같은 원리다. 거기서는 문서 안의 대명사를, 여기서는 질문 안의 대명사를 푼다.

### ⭐ 발견 2: 되쓰기가 질문을 바꿔버린다 (6번, 7번)

1차 실행의 6번이다.

```
질문:        RAG 논문은 몇 년도에 나왔고 누가 썼어?
다시 쓴 질문: GraphRAG 논문은 몇 년도에 나왔고 누가 썼어?
```

"RAG 논문"은 대명사가 아니다. 그런데 앞 대화가 전부 GraphRAG 얘기였으니 LLM이 "RAG"를
"GraphRAG"의 줄임말로 판단했다. **문맥이 없었으면 안 틀렸을 질문을 문맥 때문에 틀렸다.**
2차 실행에서는 같은 질문을 "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks
논문은..."으로 정확히 풀었다. 되쓰기 자체가 실행마다 다르다.

2차 실행의 7번은 다른 모양으로 틀렸다.

```
질문:        세 논문 중에 가장 먼저 나온 건?
다시 쓴 질문: 트랜스포머 논문과 RAG 논문 중에서 가장 먼저 나온 것은?
```

"세 논문"이 "두 논문"이 됐다. 대화 기록 최근 3턴에 GraphRAG가 안 나와서 빠뜨린 것이다.

대화형 RAG에서 되쓰기는 필수인데, 그 되쓰기가 새 오류원이 된다. 코드의 `REWRITE` 프롬프트에
"고유명사는 바꾸지 마라", "개수를 말한 부분은 그대로 둬라"를 추가했다. 실무에서는 되쓰기
전후 질문으로 둘 다 검색하기도 한다.

### ⭐ 발견 3: PDF는 마크다운과 다르다

**저자 8명이 8줄로 흩어져 있다.**

```
Ashish Vaswani∗
Google Brain
avaswani@google.com
Noam Shazeer∗
...
```

사람은 이걸 보고 "저자 8명"이라고 세지만, 800자 조각 하나에 이름과 소속과 이메일이
섞여 들어가고 "저자"라는 단어는 어디에도 없다. "저자는 몇 명"이라는 질문과 이 조각의
벡터 거리는 멀다. 5번이 엉뚱한 논문으로 간 이유다.

**수식은 깨진다.** 4쪽의 어텐션 수식을 pypdf가 뽑으면 이렇게 된다.

```
Attention(Q, K, V) = softmax(QK T
√dk
)V (1)
```

원래는 QKᵀ/√dₖ인데 분수 구조가 사라지고 줄이 끊긴다. 1차 실행에서는 이 조각이
검색조차 안 됐다. 그런데 2차 실행에서는 4쪽이 검색됐고, LLM이 깨진 텍스트에서
`softmax(QKᵀ/√dₖ)V`를 정확히 복원했다. 유명한 수식이라 LLM이 이미 알고 있어서 가능한
일이다. 처음 보는 수식이었다면 복원 못 했을 것이다. 그러니 이건 "PDF 추출이 됐다"가 아니라
"LLM의 기억이 추출 실패를 덮었다"에 가깝다.

**연도는 있는데 못 찾는다.** 세 PDF 모두 1쪽 여백에 `arXiv:2005.11401v4 [cs.CL] 12 Apr 2021`
같은 문자열이 있고 pypdf가 뽑아낸다. 그런데 "몇 년도에 나왔어?"라는 질문과 이 문자열의
벡터 거리가 멀어서 검색이 안 된다. 2차 실행의 6번이 저자 12명은 맞히고 연도만 못 찾은 이유다.
같은 1쪽에 있어도 조각이 갈리면 따로 검색된다.

**머리글이 본문에 섞인다.** attention.pdf 1쪽 첫 줄은 논문 내용이 아니라 저작권 고지다.
"Provided proper attribution is provided, Google hereby grants permission..."
이게 조각 첫머리에 들어가 임베딩을 흐린다.

### ⭐ 발견 4: 벡터로 못 푸는 질문은 여전히 못 푼다 (7번)

"세 논문 중 가장 먼저 나온 건?"은 논문 세 편의 연도를 각각 알아야 한다. 벡터 검색은
질문과 비슷한 조각을 가져오는데, "가장 먼저"라는 말과 비슷한 조각은 없다.
Q0015에서 본 전역 질문의 변형이다. 이런 건 문서마다 (제목, 연도, 저자) 메타데이터를
미리 뽑아 표로 두고 거기서 답해야 한다.

7번 답은 틀리진 않았다. "문서에서 찾을 수 없습니다"라고 했다. 프롬프트의 "근거에 없으면
모른다고 하라"가 작동한 것이다. 틀린 답보다 낫다.

### 마크다운 실험과 뭐가 달랐나

| | 지금까지 (마크다운) | 이번 (PDF) |
|---|---|---|
| 조각 수 | 3~17개 | 316개 |
| 질문 언어 vs 문서 언어 | 한국어 vs 한국어 | 한국어 vs 영어 |
| 구조 | 한 줄에 사실 하나 | 저자 블록, 수식, 표, 각주, 참고문헌 |
| 오염 | 없음 | 저작권 고지, 쪽 번호, 머리글 |

조각이 316개가 되니 k=5는 코퍼스의 1.6%다. 드디어 "벡터가 다 보고 답하는" 상황이 아니다.
그리고 한영 교차 검색이 처음이다. 임베딩 모델이 다국어를 지원해도, 한국어 질문과
영어 조각 사이의 거리는 같은 언어끼리보다 멀다.

## 🔗 코드와 연결

```bash
.venv/bin/python code/Q0019_pdf_chat.py --script     # 대본 7개 순서대로
.venv/bin/python code/Q0019_pdf_chat.py              # 직접 입력 (quit 로 종료)
.venv/bin/python code/Q0019_pdf_chat.py --rebuild    # 인덱스 다시 만들기
```

인덱스는 `data/index_q0019_pdf/`에 저장돼 두 번째부터는 바로 뜬다.

직접 입력 모드에서 해볼 만한 것: 되쓰기가 언제 틀리는지 보려면 GraphRAG 얘기를 두세 번
한 뒤 "RAG 논문은?"이라고 물어본다. 6번과 같은 현상이 재현되는지 본다.

**직접 입력 모드에서 겪은 것:** 한글을 치다 조합 중인 글자가 섞인 채 엔터를 치면
`UnicodeEncodeError: surrogates not allowed`로 죽었다. 입력을 `encode("utf-8", "ignore")`로
한 번 걸러 넣도록 고쳤다.

**처음 실행에서 겪은 것:** 조각 316개를 한 번에 임베딩하다 Azure 속도 제한(10K TPM)에 걸렸다.
배포 용량을 120K로 올리고, `config/settings.py`의 임베딩 설정에 `chunk_size=64`,
`max_retries=6`을 넣어 한 요청에 담는 양을 줄이고 실패하면 물러섰다 다시 보내게 했다.
