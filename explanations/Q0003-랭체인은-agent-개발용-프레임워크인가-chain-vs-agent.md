# Q0003 · 랭체인은 Agent 개발용 프레임워크인가? (Chain vs Agent)

- **태그**: concept
- **날짜**: 2026-06-27

## ❓ 질문
랭체인은 Agent 개발용 프레임워크인가? (Chain vs Agent)

## 💡 한 줄 답
> 아니다. 랭체인은 **"Agent도 만들 수 있는"** 종합 프레임워크지, **"Agent만 만드는"** 도구가 아니다.
> Agent는 랭체인이 제공하는 여러 기능 중 하나일 뿐이다.

## 📖 설명

랭체인([[Q0002-랭체인-langchain-이란-무엇인가]])은 LLM 앱 전반을 만드는 **종합 도구상자**이고,
그 안에 Agent 기능이 **포함**돼 있는 것이다.

```
랭체인 (LLM 앱 종합 프레임워크)
├── 단순 호출 (LLM 한 번 부르기)
├── 프롬프트 관리
├── Chain (정해진 순서대로 처리)   ← 흐름이 "고정"
├── RAG (문서 검색 + 답변)
└── Agent (LLM이 스스로 판단)      ← 흐름이 "유동적"
```

### Chain vs Agent, 핵심 차이

| | **Chain** | **Agent** |
|---|---|---|
| 흐름 | 개발자가 정해둔 순서대로 | LLM이 **스스로** 다음 행동 결정 |
| 비유 | 정해진 레시피 따라 요리 | "재료 보고 알아서 요리해" |
| 예시 | 질문 → 검색 → 답변 (항상 같음) | 질문 보고 → 검색할지/계산할지/끝낼지 LLM이 판단 |

**Agent**는 LLM에게 여러 **도구(tool)**를 쥐여주고 "어떤 도구를 언제 쓸지 네가 정해"라고
맡기는 방식이다. 요즘 말하는 "AI 에이전트"의 핵심이 이것이다.

### 이 프로젝트(RAG)와의 관계

지금 공부하는 **RAG는 보통 Chain 방식**에 가깝다 (질문 → 검색 → 답변의 흐름이 어느 정도 고정).
다만 더 복잡한 RAG는 Agent를 섞어 "검색을 한 번 더 할지 LLM이 판단"하게 만들기도 한다.

> 💡 흐름이 복잡하고 반복, 분기가 많은 Agent에는 랭체인 팀이 만든 **LangGraph**를
> 따로 쓰는 추세다 (그래프로 Agent 흐름을 설계하는 도구).
