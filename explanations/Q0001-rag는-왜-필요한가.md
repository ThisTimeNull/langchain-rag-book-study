# Q0001 · RAG는 왜 필요한가?

## ❓ 질문
RAG는 왜 필요한가?

## 💡 한 줄 답
> LLM은 학습하지 않은 사내, 최신 정보를 모르고, 모르면 그럴듯하게 지어내기(환각) 때문에,
> **답하기 전에 관련 문서를 검색해 근거로 제공**하려고 RAG를 쓴다.

## 📖 설명

LLM 혼자 답하는 것은 **암기 시험**과 같다. 외운 범위(=학습 데이터) 안에서만 답할 수 있고,
그 밖의 질문(사내 규정, 어제 뉴스, 비공개 문서)에는 모르거나 **환각**(없는 사실을 지어냄)이 생긴다.

RAG(Retrieval-Augmented Generation)는 이를 **오픈북 시험**으로 바꾼다.

1. 질문이 오면 먼저 관련 문서를 **검색(Retrieve)** 한다.
2. 찾은 근거를 프롬프트에 함께 넣어 **생성(Generate)** 한다.

→ 효과: ① 최신/사내 데이터 반영 ② 환각 감소 ③ **출처 제시** 가능.

## 🔗 코드와 연결

`code/Q0001_why_rag.py`는 가상의 사내 규정(`data/sample/company_policy.md`)으로 이를 시연한다.

- 질문: *"한빛소프트의 사내 코드네임은 뭐야?"*, 일반 LLM은 절대 알 수 없는 가상 정보다.
- 코드가 문서를 **청크로 쪼개 → 임베딩 → FAISS에 저장 → 질문과 가까운 청크를 검색**한다.
- 실행하면 `"프로젝트 미르(Mir)"`가 담긴 문장이 검색되어, **근거가 있으면 정답을 댈 수 있음**을 보여준다.

```
질문 → [검색] → "코드네임은 프로젝트 미르(Mir)" 근거 확보 → (LLM이 근거로 답변)
```

### 실행하며 배운 것 (실제 디버깅 메모)
처음엔 `chunk_size=120, k=1`로 두니 **엉뚱한 청크(식대/원격근무)** 가 검색됐다.
청크가 너무 크면 여러 사실이 한 덩어리로 묶여 검색이 흐려진다.
→ **한 줄=한 청크(`chunk_size=50`)** 로 줄이고 `k=2`로 늘리자 코드네임 문장이 정확히 검색됐다.
**청크 크기와 top-k가 검색 품질을 좌우한다**는 걸 직접 확인.
