# Q0018 · OpenAI와 DeepSeek 모델은 어떻게 다른가? (트랜스포머, 추론 모델, 오픈 가중치)

- **태그**: concept
- **날짜**: 2026-09-14
- **코드**: [`code/Q0018_model_internals.py`](../code/Q0018_model_internals.py)

## ❓ 질문
책 2장과 3장은 OpenAI와 DeepSeek 모델의 원리를 다룬다. 우리가 쓰는 모델 안에서는
무슨 일이 벌어지고, 두 회사 모델은 뭐가 다른가?

## 💡 한 줄 답
> 둘 다 **트랜스포머**다. 둘 다 **추론 모델**을 낸다. 차이는 세 가지다.
> DeepSeek는 **가중치를 공개**하고, 추론을 **강화학습만으로** 가르쳤다고 밝혔고, 훨씬 싸다.
> 그리고 우리 모델(gpt-5.4-mini)에서 확인한 것: **추론은 토큰이고 돈이며, 양을 조절할 수 있다.**

## 📖 설명

### 트랜스포머: 둘의 공통 바탕

2017년 논문 "Attention Is All You Need"에서 나온 구조다. 핵심은 **어텐션**이다.
문장을 읽을 때 각 단어가 다른 모든 단어를 얼마나 참고할지 가중치를 매긴다.

```
"인증 서비스는 인프라팀 소관이라 김철수가 붙었다"

'김철수'를 처리할 때 -> '붙었다'와 '인프라팀'에 큰 가중치, '소관이라'에 작은 가중치
```

이전 방식(RNN)은 단어를 앞에서부터 순서대로 읽어서 긴 문장의 앞부분을 잊었다.
어텐션은 문장 전체를 한 번에 보니 그 문제가 없고, 병렬 계산이 되어 크게 만들 수 있다.

GPT는 이 구조로 "다음 단어 맞히기"를 인터넷 규모 텍스트로 학습한 것이다.
그게 전부다. 질문에 답하는 것도, 코드를 짜는 것도, 다음 단어를 잘 맞히는 능력에서 나온다.

Q0006에서 본 임베딩 모델(`text-embedding-3-small`)도 트랜스포머다. 다음 단어를 생성하는 대신
문장 전체를 벡터 하나로 요약하도록 학습한 것이다.

### 추론 모델: 답하기 전에 생각하는 모델

2024년 OpenAI o1부터 시작된 흐름이다. 일반 모델은 질문을 받으면 바로 답을 생성한다.
추론 모델은 **먼저 혼잣말로 풀이 과정을 쓰고**, 그 다음 답을 쓴다. 혼잣말은 사용자에게
안 보이지만 토큰으로 생성되고 과금된다.

우리 모델에서 확인한 것이다.

```
[b] reasoning_effort 를 바꾸면
  low     1.8초  추론  46토큰
  medium  2.2초  추론 122토큰
  high    2.3초  추론 131토큰
```

`reasoning_effort`로 생각의 양을 조절할 수 있다. 쉬운 질문은 low로도 맞는다.
**RAG 답변 생성처럼 근거가 이미 주어진 일에는 low가 싸고 빠르다.** 우리 프로젝트에서
지금까지 기본값(medium)으로 돌렸는데, 생성 단계는 low로 낮춰도 될 가능성이 크다.

### 확인하기 전엔 모른다: temperature

이 프로젝트에서 저지른 실수를 기록해둔다. Azure에 모델을 배포할 때 "gpt-5 계열은 추론
모델이라 temperature를 안 받는다"고 판단했고, 그래서 결정론적 실험이 안 된다고 했다.
`config/settings.py`에도 그렇게 주석을 달았다.

Q0018에서 실제로 돌려보니 **받고, 동작한다.**

```
temperature=0    -> ['742', '742', '742', '742', '742', '742']  (1종)
temperature=1.5  -> ['742', '742', '482', '742', '742', '487']  (3종)
```

초기 o1과 o3는 실제로 temperature를 거부했다. 그 지식이 gpt-5.4-mini에는 맞지 않았다.
모델은 몇 달 단위로 바뀐다. **외운 것을 쓰지 말고 쓰는 모델에서 직접 확인한다.**
주석과 메모리는 정정했다.

### DeepSeek: 무엇이 달랐나

2025년 1월 DeepSeek-R1이 나오면서 세 가지로 주목받았다.

**첫째, 가중치를 공개했다.** OpenAI 모델은 API로만 쓴다. DeepSeek는 모델 파일을 내려받아
내 서버에서 돌릴 수 있다. 이 맥에 설치된 ollama의 qwen3처럼. 데이터를 밖으로 못 보내는
환경이나 비용을 극단적으로 줄여야 할 때 선택지가 된다.

**둘째, 추론을 강화학습만으로 가르쳤다고 밝혔다.** 보통은 사람이 쓴 풀이 예시로 먼저 가르치고
강화학습으로 다듬는다. DeepSeek는 R1-Zero라는 실험에서 풀이 예시 없이 "정답을 맞히면 보상"만으로
모델이 스스로 풀이 과정을 만들어내더라고 보고했다. 그 과정이 논문으로 공개돼 다른 팀이
따라 할 수 있게 됐다.

**셋째, 싸다.** API 가격이 OpenAI의 수십분의 일이었다. 학습 비용도 훨씬 적었다고 주장했다.

### 그래서 우리 프로젝트에 어떤 의미인가

| | OpenAI (Azure 경유) | DeepSeek |
|---|---|---|
| 접근 | API만 | API 또는 내려받기 |
| 한국어 | 좋음 | 준수함, 영어와 중국어가 주력 |
| 구조화 출력 | 안정적 (Q0015에서 확인) | 모델에 따라 편차 |
| 비용 | 높음 | 낮음 |
| 데이터 반출 | Azure 리전 안 | 내 서버면 없음 |

`config/settings.py`에 `get_deepseek_llm()`이 이미 있다. 책 6장은 5장 실습을 DeepSeek로
반복하는 것이다. 같은 RAG 파이프라인에서 모델만 바꿔 **답변 품질과 비용이 어떻게 갈리는지**
재보는 게 다음 실험이 될 수 있다. Q0008에서 임베딩 모델을 바꿨을 때처럼.
