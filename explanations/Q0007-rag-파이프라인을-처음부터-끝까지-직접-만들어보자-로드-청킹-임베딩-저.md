# Q0007 · RAG 파이프라인을 처음부터 끝까지 직접 만들어보자 (로드→청킹→임베딩→저장→검색→답변)

- **태그**: vectorrag
- **날짜**: 2026-08-27
- **코드**: [`code/Q0007_rag_pipeline.py`](../code/Q0007_rag_pipeline.py)

## ❓ 질문
지금까지 부품은 하나씩 봤다. 그럼 **실제로 도는 RAG 하나**는 어떻게 만드나?

## 💡 한 줄 답
> **6단계가 전부다: 로드 → 청킹 → 임베딩 → 저장 → 검색 → 생성.**
> 그리고 RAG의 정체는 결국 **"질문에 관련 근거를 자동으로 붙여 프롬프트를 조립해주는 것"**이다.

## 📖 설명

### 전체 그림

```
 [준비 단계, 문서가 바뀔 때만 한 번]
   문서 파일 ──①로드──> Document ──②청킹──> 조각 7개
                                              │
                                          ③임베딩 (384차원 벡터)
                                              │
                                          ④저장 (FAISS 인덱스 → 파일)
 ─────────────────────────────────────────────────────────────
 [질의 단계, 질문할 때마다]
   질문 ──③임베딩──> 질문 벡터 ──⑤검색──> 가까운 조각 k개
                                              │
                                     ⑥근거+질문으로 프롬프트 조립 → LLM → 답변
```

**임베딩(③)이 양쪽에 등장하는 게 핵심**이다. 문서도 질문도 같은 모델로 벡터를 만들어야
같은 좌표계에서 거리를 잴 수 있다. (그래서 인덱스를 만든 모델과 검색할 때 모델이 달라지면 안 된다.)

### 단계별로

**① 로드**, 파일을 `Document`(본문 `page_content` + `metadata`)로 바꾼다.

```python
docs = DirectoryLoader("data/sample", glob="*.md", loader_cls=TextLoader).load()
```
`metadata["source"]`에 파일 경로가 들어가고, 이게 나중에 **출처 표시**의 근거가 된다.
PDF, CSV, 웹, Notion 등 **로더만 갈아끼우면** 나머지 파이프라인은 그대로다.

**② 청킹**, 긴 문서를 조각낸다. 왜?

1. 문서 전체를 LLM에 넣으면 비싸고, 길면 아예 안 들어간다
2. **검색의 단위가 조각**이다, 조각이 크면 관련 없는 내용이 딸려오고, 작으면 문맥이 끊긴다

```python
RecursiveCharacterTextSplitter(
    chunk_size=200, chunk_overlap=40,
    separators=["\n## ", "\n- ", "\n", " ", ""],   # 위에서부터 시도한다
)
```
`separators`가 중요하다. "200자에서 무조건 자르기"가 아니라 **`## 제목` → `- 항목` → 줄바꿈 →
공백** 순으로 시도해서 **의미 단위를 최대한 지키며** 자른다. `overlap`은 문장이 조각 경계에서
잘려 뜻을 잃는 걸 막는 완충 장치다.

**③④ 임베딩 & 저장**, 조각을 벡터로 바꿔 FAISS에 넣고 **파일로 저장한다.**

```python
store = FAISS.from_documents(chunks, embeddings)
store.save_local("data/index_q0007_c200_o40")   # index.faiss + index.pkl
```
임베딩 계산은 느리고(API면 돈이 든다) 문서가 안 바뀌면 결과가 같다 → **저장해두고 재사용**한다.

> ⚠️ 실전 함정: 인덱스를 캐시하면 `chunk_size`를 바꿔도 **예전 인덱스를 그대로 읽어서**
> "왜 결과가 안 변하지?" 하게 된다. 그래서 코드에서는 **폴더 이름에 설정을 박아뒀다**
> (`index_q0007_c200_o40`). 설정을 바꾸면 자동으로 새 인덱스가 만들어진다.

**⑤ 검색**, `k`개의 가까운 조각을 가져온다.

```python
retriever = store.as_retriever(search_kwargs={"k": 3})
```

**⑥ 생성**, 근거를 붙여 LLM에게 묻는다. [[Q0006-랭체인은-실제로-어떻게-사용하나-lcel-파이프-로-조립하기]]에서 본 그 파이프다.

```python
chain = (
    RunnableParallel(
        context=retriever | RunnableLambda(format_docs),   # 질문 → 검색 → 문자열
        question=RunnableLambda(lambda q: q),
    )
    | prompt | model | StrOutputParser()
)
```

프롬프트에 이 문장을 넣은 게 중요하다:

> "근거에 없는 내용은 절대 지어내지 말고 '문서에서 찾을 수 없습니다'라고 답하세요."

RAG의 목적이 환각을 줄이는 것([[Q0001-rag는-왜-필요한가]])이므로, **모르면 모른다고 하게**
만들어야 한다. 이 한 줄이 없으면 LLM은 근거를 무시하고 아는 척을 한다.

### ⭐ RAG의 정체, 결국 프롬프트 조립기

API 키가 없을 때 코드는 LLM을 부르는 대신 **실제로 LLM에 들어갈 프롬프트 전문**을 출력한다.
이게 이 질문에서 제일 볼 만한 부분이다.

```
Human: 당신은 사내 규정 안내 담당자입니다.
아래 [근거]에 있는 내용만 사용해 한국어로 간결하게 답하세요.
근거에 없는 내용은 절대 지어내지 말고 '문서에서 찾을 수 없습니다'라고 답하세요.

[근거]
(1) [hr_guide.md]
## 휴가
- 연차는 입사 첫 해 11일, 2년 차부터 15일이 부여된다.
- 연차는 사용 3일 전까지 신청해야 하며, 팀장 승인 후 확정된다.
...
[질문] 연차를 쓰려면 며칠 전에 신청해야 하나요?
[답변]
```

**"연차 신청"이라는 단어만 던졌는데 관련 규정이 알아서 붙어 들어갔다.** 그게 RAG의 전부다.
마법처럼 보이던 게 결국 문자열 조립이라는 걸 눈으로 확인하는 게 이 단계의 목적이다.

## 🔗 코드와 연결

```bash
.venv/bin/python code/Q0007_rag_pipeline.py
.venv/bin/python code/Q0007_rag_pipeline.py "금요일에 배포해도 되나요?"
```

실습용 문서 2개를 새로 넣었다: `data/sample/hr_guide.md`(휴가, 근무시간, 교육),
`data/sample/dev_handbook.md`(코드리뷰, 배포, 장애대응). 기존 `company_policy.md`까지 3개 → 조각 7개.

**"금요일에 배포해도 되나요?" 실행 결과:**

| 순위 | 출처 | 내용 |
|---|---|---|
| 1 | `dev_handbook.md` | "금요일 배포는 원칙적으로 금지한다" ✅ **정확** |
| 2 | `hr_guide.md` | 자기계발비 100만원 ❌ 무관 |
| 3 | `company_policy.md` | 사내 코드네임 ❌ 무관 |

**1위는 정확한데 2, 3위는 완전히 무관하다.** 조각이 7개뿐인데 `k=3`을 요구하니
관련 없는 것까지 억지로 채워진 것이다. 벡터 검색은 "가까운 순 k개"를 줄 뿐
**"관련 있는 것만" 주지 않는다**, 거리 임계값이라는 개념이 기본적으로 없다.

무관한 근거가 섞이면 LLM이 헷갈리고 토큰도 낭비된다. **이게 바로 다음 질문(튜닝)의 출발점이다.**
