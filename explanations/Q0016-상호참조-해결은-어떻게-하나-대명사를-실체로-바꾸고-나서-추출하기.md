# Q0016 · 상호참조 해결은 어떻게 하나? (대명사를 실체로 바꾸고 나서 추출하기)

- **태그**: graphrag
- **날짜**: 2026-09-13
- **코드**: [`code/Q0016_coreference.py`](../code/Q0016_coreference.py)

## ❓ 질문
Q0012에서 `(그쪽) -[의존]-> (우리 쪽)` 같은 대명사 노드가 나왔다. 추출 전에 대명사를
실명으로 바꾸면 해결되나?

## 💡 한 줄 답
> **대명사 노드는 사라졌다** (평균 1.5개 → 0개). 하지만 **재현율은 오르지 않았다**.
> 놓친 정답은 대명사 탓이 아니라 **관계 방향을 거꾸로 읽은** 탓이었다.
> 전처리 하나는 자기 문제 하나만 푼다.

## 📖 설명

### 방법

추출하기 전에 문서를 한 번 다시 쓴다. 조각이 아니라 **문서 전체**를 준다.
제목, 참석자, 서명에서 누구인지 알 수 있기 때문이다.

```
전: 저는 결제 API를 주로 봤습니다. 팀장님은 이민수 님이고,
후: 박영희는 결제 API를 주로 봤습니다. 팀장님은 이민수 님이고,

전: 인증 서비스는 우리 팀 소관이라 김철수가 바로 붙었다.
후: 인증 서비스는 인프라팀 소관이라 김철수가 바로 붙었다.
```

인수인계 메모는 "박영희 → 후임자"라는 제목에서 "저"가 박영희임을 알아냈다.
회의록은 "인프라팀 주간 회의"라는 제목에서 "우리 팀"이 인프라팀임을 알아냈다.
장애 회고는 대명사가 없어서 한 줄도 안 바뀌었다.

### 결과 (각 2회)

| | 재현율 | 정답 외 관계 | 대명사 노드 |
|---|:---:|:---:|:---:|
| 원문 그대로 | 91% (11, 9) | 11.5개 | **1.5개** (후임자, 우리 쪽) |
| 상호참조 해결 후 | 82% (9, 9) | 14.5개 | **0개** |

### ⭐ 발견 1: 대명사 문제는 확실히 풀렸다

두 번 모두 대명사 노드가 0개다. `그쪽`, `우리 쪽`, `후임자` 같은 노드가 사라졌다.
이건 설계한 대로 됐다.

### ⭐ 발견 2: 재현율은 오르지 않았다. 원인은 다른 데 있었다

상호참조를 풀고도 두 번 다 같은 정답 2개를 놓쳤다.

```
놓친 것:   (인프라팀) -[운영]-> (인증 서비스)
           (인프라팀) -[운영]-> (알림 서비스)
```

그런데 그래프를 보면 이게 있다.

```
(인증 서비스) -[운영]-> (인프라팀)     ← 방향이 거꾸로
```

원문은 "인증 서비스는 인프라팀 소관이라"다. 주어가 인증 서비스니까 LLM이
인증 서비스를 출발점으로 잡았다. "소관"이라는 말은 방향을 정해주지 않는다.
**상호참조 해결은 "누구"를 바로잡지만 "어느 쪽으로"는 손대지 않는다.**

원문 그대로 1회에서 11/11이 나온 건 운이다. 2회는 9/11이었다. LLM 추출은 매번 다르다.
2회 실험으로는 82%와 91%의 차이가 의미 있는지 말할 수 없다.

### ⭐ 발견 3: 실명이 늘면 관계도 늘어난다

정답 외 관계가 11.5개에서 14.5개로 늘었다. "저"가 "박영희"로 바뀌니 박영희를 주어로 하는
관계가 더 많이 뽑혔다. 그중에는 맞는 것도 있고 틀린 것도 있다.

```
(박영희) -[소속]-> (결제팀)      맞음. 정답에도 있음
(김철수) -[의존]-> (인증 서비스)  틀림. 사람이 서비스에 의존하지 않는다
```

대명사를 없애면 LLM이 문장을 더 많이 "이해"한다. 그 이해가 맞을 때도 틀릴 때도 있다.

### 왜 추출 전에 해야 하나

추출 후에 `그쪽` 노드를 지우면 되지 않나? 안 된다.
`(알림 서비스) -[소속]-> (그쪽)`처럼 **관계가 이미 엉뚱한 노드에 붙어 있다.**
`그쪽`을 지우면 알림 서비스가 어디 소속인지 정보 자체가 사라진다.
대명사를 실명으로 바꾸는 건 추출 전에만 의미가 있다.

### 전처리는 하나씩만 푼다

지금까지 만난 추출 문제와 그걸 푸는 도구를 정리하면 이렇다.

| 문제 | 예 | 푸는 도구 | 확인한 곳 |
|---|---|---|---|
| 이름 표기 | 결제 Api ≠ 결제 API | 원문 대조 정합 | Q0011 |
| 대명사 | 그쪽, 우리 팀 | 상호참조 해결 (이번) | Q0016 |
| 세는 단위 | 원인 이름 23가지 | 고정 스키마 (택일 강제) | Q0015 |
| **관계 방향** | 인증 서비스 → 인프라팀 | **아직 없음** | Q0016에서 발견 |
| 누락 | 24개 중 8개 | (청크 크기로도 안 됐음) | Q0011 |

방향 문제는 다음 실험에서 다룬다. 문장 틀이 있는 부분은 규칙이 읽으면 방향이 틀릴 일이 없다.

## 🔗 코드와 연결

```bash
.venv/bin/python code/Q0016_coreference.py
.venv/bin/python code/Q0016_coreference.py --runs 3
```

| 함수 | 역할 |
|---|---|
| `resolve()` | 문서 전체를 LLM에 주고 대명사만 실명으로 바꾸게 함 |
| `extract()` | Q0012와 같은 추출 + 이름 정합 |
| `score()` | 재현율, 정답 외 개수, 대명사 노드 개수 |

`REWRITE` 프롬프트의 4번 규칙("내용, 순서, 문장 수를 바꾸지 마세요")이 중요하다.
이게 없으면 LLM이 문서를 요약하거나 재구성해 버린다.
